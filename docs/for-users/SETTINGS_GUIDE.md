# Настройки сайта

Все настройки — **Настройки сайта** (`?tab=config_vars`).  
Секции сворачиваются в **аккордеон**.

---

## 📞 Контактная информация

| Поле | HTML | Валидация |
|------|------|-----------|
| **Название компании** | ✅ | Санитайзер |
| **Слоган** | ✅ | Санитайзер |
| **Телефон** | ❌ | Только `0-9+` |
| **Email** | ❌ | `FILTER_VALIDATE_EMAIL` |
| **Адрес** | ❌ | `e()` при выводе |

**HTML разрешён** — можно `<span>`, `<b>`, `<br>`, ссылки.  
**HTML запрещён** — санитайзер уберёт при попытке вставить.

**Пример** **названия**:
```html
AlPin<span class="text-[var(--primary-color)]">CMS</span>
```
**Результат** — «**AlPin**» **чёрным**, «**CMS**» **основным** **цветом**.

## 🎨 Цветовая схема

**8 цветов:**

| Переменная | Где используется |
|-----------|------------------|
| `primary_color` | Кнопки, ссылки, акценты |
| `primary_dark` | Hover кнопок |
| `bg_main` | Фон страницы |
| `bg_card` | Фон карточек |
| `bg_section` | Фон секций |
| `text_main` | Основной текст |
| `text_muted` | Второстепенный текст |
| `border_color` | Границы |

**Формат:** `#RRGGBB`.  
**Синхронизация:** color-picker ↔ text-input.

**В** **CSS** **используются** **как** **CSS-переменные:**
```css
:root {
    --primary-color: #10B981;
    --primary-dark: #059669;
    ...
}
```

## 🔍 Технический SEO

Раздел в Настройках сайта → **SEO настройки** → блок **«Технический SEO»**.

### Что здесь

- **Генерировать `sitemap.xml`** — карта сайта для поисковиков.
- **Генерировать `robots.txt`** — правила индексации.
- **Автообновлять при изменении страниц** — обновление файлов при каждом сохранении/удалении страницы.

**По умолчанию обе галочки генерации сняты.** Включите, если хотите, чтобы файлы создавались.

### Ручная генерация

Кнопка **«Пересобрать»** (или «Генерировать») — создаёт оба файла прямо сейчас.

**Когда использовать:**
- Первый раз после включения галочек.
- Если что-то поменяли в настройках, а автообновление выключено.
- Если хочется «на всякий случай» обновить.

### Что попадает в sitemap

**Только опубликованные страницы:**
- `status = published`.
- Без истёкшего `unpublish_at`.

**Не попадают:**
- Черновики, запланированные, снятые с публикации.
- Preview-URL (даже с активным токеном).
- Служебные URL (`/config/`, `/data/`, `/cache/`).

### Что попадает в robots

**Запрещаем:**
- `/config/` — админка.
- `/data/` — пользовательские данные.
- `/cache/` — кеш.
- `/*?preview=` — preview-ссылки.

**Разрешаем:** всё остальное.

**Плюс:** указываем `Sitemap:` на sitemap.xml.

### Автоматическое обновление

**Если включена галочка «Автообновлять»:**
- Файлы пересобираются при **сохранении** страницы.
- При **удалении** страницы (в корзину).
- При **восстановлении** из корзины.
- При **клонировании** страницы.
- При **смене главной** страницы.

**Если выключена** — файлы обновляются только вручную или через cron.

### Крон для планировщика хостинга

В блоке «Технический SEO» — **URL для cron**.

**Рекомендуемая частота:** раз в сутки.

**Как настроить:**
1. Скопируй URL.
2. В панели хостинга (ISPmanager, cPanel, Plesk) → **Планировщик** → добавь задачу.
3. Периодичность: `0 3 * * *` (каждый день в 3:00).

**Токен общий** с бэкапами и публикацией. Если перегенерируешь токен — обнови URL во всех трёх кронах.

### 301-редиректы

**Работают автоматически.** Если ты переименовал страницу (`about` → `o-kompanii`), старая ссылка `/about` будет **редиректить** (301) на `/o-kompanii`.

**Никакой настройки не требуется.**

Это сохраняет SEO-вес и не ломает внешние ссылки.

## ⚡ Кеширование страниц

| Параметр | Что делает |
|----------|-----------|
| **Включить кеширование** | Готовый HTML в `/cache/pages/` |
| **Время жизни** | 1ч / 6ч / 24ч / 7д / бессрочно |

**Статистика:** **страниц** **в** **кеше**, **объём**.

**Кнопка** **«Очистить** **весь** **кеш»** — **удаляет** **всё**.

**Когда** **включать:** **на** **проде**. **На** **разработке** — **выключено** (**видеть** **изменения** **сразу**).

**Автоматическая** **очистка** **при:**
- **Сохранении** **страницы** — **только** **её** **кеш**.
- **Обновлении** **модуля** — **весь** **кеш** **ассетов**.
- **Изменении** **настроек** **ассетов** — **весь** **кеш**.

## 💻 Произвольный код

### Custom CSS

**Вставляется** **в** `<style>` **в** `<head>`.

**Пример:**
```css
.btn-custom {
    background: linear-gradient(90deg, #10B981, #059669);
    box-shadow: 0 4px 20px rgba(16, 185, 129, 0.3);
}
```

### Custom JS

**Вставляется** **в** `<script>` **перед** `</body>`.

**Пример:**
```js
document.addEventListener('DOMContentLoaded', function() {
    console.log('Custom JS loaded');
});
```

**Внимание:** **это** **доверенный** **код** — **санитайзер** **не** **применяется**. **Проверяй** **перед** **вставкой**.

## 🗝 Интеграция с планировщиком

Секция для настройки **кронов** (задач по расписанию):
- **Резервное копирование** — авто-бэкапы.
- **Автопубликация страниц** — переходы `scheduled → published` и `published → archived`.
- **Обновление sitemap/robots** — генерация SEO-файлов.

**Где находится:** Настройки сайта → Интеграция с планировщиком.

### Токен крона

**Один токен** используется **всеми** крон-задачами:

- **Резервное копирование** — авто-бэкапы.
- **Автопубликация страниц** — переходы статусов.
- **Обновление sitemap.xml и robots.txt.**

**Формат:** 32 hex-символа (генерируется автоматически при первом обращении).

### Перегенерация токена

Кнопка **«Перегенерировать»** справа от поля с токеном.

**Как работает:**

1. Клик → подтверждение (⚠️ предупреждение, что все крон-задачи сломаются).
2. Токен **визуально обновляется** в поле и в URL кронов.
3. **В `settings.json` записывается только при нажатии «Сохранить настройки»**.

**Если не сохранить** — токен останется старым (можно передумать).

**После сохранения** — обнови URL в планировщике хостинга, иначе крон вернёт 403.

### URL для планировщика

**Три URL** отображаются в секции:

**Резервное копирование:**
```
https://твой-сайт/config/cron/backup.php?token=<токен>
```

**Автопубликация страниц:**
```
https://твой-сайт/config/cron/publish.php?token=<токен>
```

**Обновление sitemap.xml и robots.txt:**
```
https://твой-сайт/config/cron/seo.php?token=<токен>
```

**Скопируй URL** и вставь в планировщик хостинга (ISPmanager, cPanel, Plesk, DirectAdmin).

**Рекомендуемая частота:**
- Бэкап — 1 раз в сутки.
- Публикация — каждые 5–15 минут.
- SEO — 1 раз в сутки.

### Протокол

URL формируется **динамически** — `http://` или `https://` в зависимости от текущего соединения. Если сайт работает по HTTPS — URL будет с HTTPS. Если по HTTP (например, локально) — с HTTP.

**На проде — всегда HTTPS.**

### Что если не настроить (в планировщике хостинга)

**Резервное копирование:** авто-бэкапы не работают. Но **можно делать вручную** (кнопка «Запустить резервное копирование»).

**Автопубликация:** страницы с `scheduled` не публикуются автоматически. **Виртуальный крон** (см. ниже) может их обработать при входе админа. Но если админ не заходит несколько дней — страница не будет опубликована.

**SEO:** sitemap и robots не обновляются по расписанию. Но можно:
- Вручную нажать **«Пересобрать»** в секции SEO.
- Включить **«Автообновлять при изменении страниц»** — файлы пересобираются при каждой правке.

### Виртуальный крон публикации

**Не требует настройки.** Работает автоматически при входе в админку — не чаще 1 раза в 5 минут.

**Проверяет** страницы с истёкшими `publish_at` / `unpublish_at` и применяет переходы статусов.

**Плюс:** не нужен планировщик на хостинге.

**Минус:** работает только когда админ активен.

**Можно комбинировать** — виртуальный крон + системный. Друг другу не мешают.

## 💾 Сохранение

**Кнопка** **«Сохранить** **настройки»** **внизу** **страницы**.

**При** **сохранении:**
- **Данные** **пишутся** **в** `data/settings.json`.
- **Логирование** (`settings_save`).
- **Flash-сообщение** «Настройки сайта успешно сохранены!».
- **Очистка** **кеша** (**если** **изменились** **ассеты**).

**Ошибки:**
- **HTML** **в** **запрещённом** **поле** → **«Поле "X": Обнаружено недопустимое содержимое: ...»**.
- **Невалидный** **email** → **«Некорректный email»**.
- **Ошибка** **записи** → **«Ошибка записи на диск»**.
