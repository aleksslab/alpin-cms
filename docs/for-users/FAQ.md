# FAQ и решение проблем

## 🔧 Установка и настройка

### 500 Internal Server Error при открытии сайта

**Причины:**
- **Неверные** **права** **на** `config/data/`, `cache/`, `data/`.
- **Старая** **версия** **PHP** (< 7.4).
- **Ошибка** **в** `.htaccess`.

**Решение:**
```bash
chmod 755 data/ config/data/ cache/
```
**Проверь** `error.log` **Apache** — **там** **будет** **конкретная** **ошибка**.

### 404 на всех страницах кроме главной

**Причина:** `.htaccess` **не** **работает** (**mod_rewrite** **выключен** **или** `AllowOverride None`).

**Решение:**
- **В** `httpd.conf` — `AllowOverride All` **для** **директории** **сайта**.
- **Проверь** **включён** **ли** `mod_rewrite` (**в** **настройках** **Apache**).
- **Перезапусти** **Apache**.

### Логин не работает

**Причины:**
- **Неверный** **пароль**.
- **Повреждён** `credentials.json`.
- **Отсутствует** `.pepper`.

**Решение:**
1. **Перегенерируй** **хеш** **через** **«Конфигурация** **ключей»**.
2. **Обнови** `config/data/credentials.json`.
3. **Проверь** **наличие** `config/data/.pepper` (**не** **удаляй**!).
4. **Очисти** **cookies** **браузера** (`PHPSESSID`).
5. **Попробуй** **в** **режиме** **инкогнито**.

### Кеш не сбрасывается

**Решение:**
- **Настройки** **сайта** → **Кеширование** → **Очистить** **весь** **кеш**.
- **Вручную**: **удали** `cache/pages/*.html` и `cache/assets/*`.
- **Проверь** **права** **на** `cache/` (`755`).

### Изменения в админке не отображаются на фронте

**Причина:** **кеш** **включён**.

**Решение:**
- **Очисти** **кеш** **в** **админке**.
- **Или** — **выключи** **кеширование** **на** **время** **разработки**.
- **Проверь** `cache/pages/` — **есть** **там** **старая** **версия**?

## 🕘 История изменений

### Кнопка «Открыть историю» не появляется в редакторе

**Причина:** история **выключена** в настройках.

**Решение:**
- Открой **Настройки сайта** → **История изменений**.
- Поставь галочку **«Хранить историю изменений страниц»**.
- **Сохрани** настройки.

### История не пополняется при сохранении страницы

**Причины:**
- История **выключена**.
- Ты **не менял** ничего — снапшот создаётся **только при реальных изменениях** (дедупликация).
- Такое же состояние **уже есть** в последнем снапшоте.

**Решение:**
- Проверь галочку в настройках.
- Внеси реальное изменение (правка текста, добавление модуля) — сохрани.
- Если состояние **идентично** последнему снапшоту — **дубль не создаётся** (это норма).

### Восстановил страницу из истории — статус сбросился на «Черновик»

**Такого быть не должно.** Откат восстанавливает **только контент**, статус **не трогается**.

**Если произошло:**
- Проверь версию CMS (баг был в ранних сборках v1.7.0).
- Сообщи в [Issues](https://github.com/AlekSSLab/alpin-cms/issues) — с шагами воспроизведения.

**Что делать сейчас:**
- Открой страницу → смени статус вручную.
- Или откатись к **другой** версии, где статус был корректным.

### После отката пропал URL (slug)

**Так задумано.** Откат восстанавливает **только контент** — `slug` остаётся **текущий**.

**Пример:** переименовал `about` → `o-kompanii`, потом откатил контент к старой версии. Страница останется на `/o-kompanii`.

**Почему:** URL — «адрес страницы», он не должен меняться от отката контента. 301-редиректы со старых slug'ов продолжают работать.

### После отката пропала preview-ссылка

**Так задумано.** Откат восстанавливает **только контент** — `preview_token` остаётся **текущий**.

**Если нужно** вернуть старую preview-ссылку — создай новую кнопкой в форме редактирования.

### История занимает много места на диске

**Решение:**
1. Проверь **Настройки сайта** → **История изменений** → **Статистика**.
2. Если объём большой:
   - Уменьши **лимит версий** (например, 20 → 10).
   - Или нажми **«Очистить всю историю»** — удалит **все** снапшоты.

**Помни:** при уменьшении лимита старые версии удаляются **не сразу** — при следующем сохранении (ротация).

### Удалил страницу в корзину — история сохранилась?

**Да.** При перемещении в корзину история **сохраняется**.

**Окончательное удаление** (из корзины) — **удаляет историю** страницы вместе с файлом.

### Можно ли откатить **сам** откат?

**Да.** Перед откатом **автоматически сохраняется** снапшот текущего состояния. Он появится в истории — можно откатиться к нему.

### История у меню / настроек / модулей?

**Нет.** История работает **только для страниц**. Меню, настройки, модули — **без истории**.

## 🎨 Модули и конструктор

### Модуль не отображается на странице

**Причины:**
- **Модуль** **не** **распакован** (**статус** «**в** **архиве**»).
- **Пустые** **обязательные** **поля**.
- **Ошибка** **в** **данных** **модуля**.
- **Кеш** **показывает** **старую** **версию**.

**Решение:**
1. **Управление** **модулями** → **проверь** **статус** → **«Распаковать»**.
2. **Открой** **настройки** **модуля** **в** **конструкторе** — **заполни** **обязательные** **поля**.
3. **Очисти** **кеш**.
4. **Открой** `data/pages/{id}.json` — **проверь** **есть** **ли** `type` **модуля**.

### Модуль «съехал» / вёрстка сломалась

**Причины:**
- **Конфликт** **Tailwind-классов**.
- **Ширина** **колонок** **не** **суммируется** **в** `12/12`.
- **Модуль** **имеет** **свою** **вёрстку**, **конфликтует** **с** **соседями**.

**Решение:**
- **Упростить** **классы** **ряда**/**колонки**.
- **Проверить** **сумму** **ширины** **колонок** (**например**, `w-6/12 + w-6/12`).
- **Проверить** **на** **разных** **разрешениях**.

### Не могу загрузить модуль (ZIP)

**Причины:**
- **Размер** > 10 МБ.
- **Отсутствует** `manifest.json`.
- **Формат** не ZIP.
- **`manifest.id`** **невалидный** (**только** **a-z**, **0-9**, `-`, `_`).

**Решение:**
- **Проверь** **структуру** **ZIP**.
- **Уменьши** **размер** (**сожми** **картинки**).
- **Проверь** `manifest.json` **на** **валидность**.

### Модуль «зависает» при добавлении

**Причина:** **модуль** **не** **распакован**, **CMS** **пытается** **распаковать**.

**Решение:** **подожди** 5-10 **сек**, **обнови** **страницу**.

## 🖼 Медиа

### WebP-файлы не создаются при загрузке

**Причины:**
- Галочка **«Конвертировать в WebP»** выключена в настройках.
- На сервере **нет GD** с поддержкой WebP или **Imagick**.
- Загружается **не jpg/png**, а `gif`, `svg`, `ico`, `avif` (они не конвертируются).

**Решение:**
1. **Настройки сайта** → **Медиа** → проверь галочку.
2. Если под галочкой — предупреждение «не поддерживается» — **проверь PHP**:
   - `php -m | grep gd` — есть ли GD.
   - Или `info.php` → `gd` в списке расширений.
3. Если GD есть, но WebP **не поддерживается** (старая сборка) — установи **Imagick** или обнови PHP.
4. Проверь формат файла: `jpg`, `jpeg`, `png` — конвертируются, остальные — нет.

### .webp создаётся, но на фронте картинка остаётся .jpg

**Причины:**
- **Кеш страницы** — HTML закеширован с старым `src`.
- `.webp` лежит **не рядом** с оригиналом (например, в другой папке).

**Решение:**
- **Настройки сайта** → **Кеширование** → **Очистить весь кеш**.
- Проверь через проводник: `images/foo.jpg` и `images/foo.webp` — **в одной папке**.
- Ctrl+F5 в браузере.

### Lazy loading не работает

**Причины:**
- Галочка выключена.
- Смотришь на **hero** или **логотип в хедере** — там lazy **не применяется** (LCP).
- Страница в кеше.

**Решение:**
- **Настройки сайта** → **Медиа** → **Lazy loading** — вкл.
- Очисти кеш.
- Проверь DevTools → Elements → найди `<img>` в **контентной части** (не в hero). Должны быть `loading="lazy"` и `decoding="async"`.

### Картинки «прыгают» при прокрутке

**Причина:** при `lazy` браузер не знает **размер** картинки до загрузки → резервирует 0 высоты → при загрузке «прыгает» контент.

**Решение:**
- **В hero** и **карусели** lazy **не применяется** — там этой проблемы нет.
- **Для остальных** — проблема **редкая** (браузеры обычно справляются).
- **Если критично:** выключи lazy для конкретного модуля (правка кода) или дождись добавления `width`/`height` в модулях (в будущем).

### Как удалить все .webp

**Настройки сайта** → **Медиа** → кнопка **«Удалить все .webp»**.

**Что удалит:** только `.webp`, у которых **есть парный** `jpg`/`png`.

**Что не тронет:** нативные `.webp` (без оригинала) и оригиналы.

**Зачем:** если включил WebP, потом понял, что не нужно, или хочешь уменьшить объём диска.

### Как конвертировать существующие картинки

**Настройки сайта** → **Медиа** → блок **«Без .webp: N»** → кнопка **«Конвертировать N существующих»**.

Обрабатывает **все** jpg/png в `images/` (**включая подпапки**) **шагами** (по 10 файлов) с прогресс-баром.

**Оригиналы сохраняются.** Процесс можно прервать — часть уже сконвертируется.

### Перенёс сайт — WebP перестал работать

**Причина:** на новом сервере **нет GD/Imagick**, а в `settings.json` — `media_webp_enabled: true`.

**Что произойдёт:**
- `.webp` **не создаются**.
- Старые `.webp` **остаются** и **работают** (файлы физически на диске).
- В настройках — **двойное предупреждение**.

**Решение:**
- **Новые картинки** — загружаются **без** `.webp` (тихо, без ошибок).
- Если хочешь включить обратно — **установи GD/Imagick**.
- При сохранении настроек — галочка **автоматически** станет `false` (починится).

### WebP: качество — какое ставить

**По умолчанию — 82.** Баланс качества и размера.

- **70–75** — сильное сжатие, подходит для **фонов**, **декоративных** картинок.
- **82** — стандарт, для **большинства**.
- **88–92** — если картинки «поплыли» (артефакты видны).
- **95+** — почти без сжатия, размер **как у оригинала**. Не имеет смысла.

**Меняется в:** Настройки → Медиа → Качество WebP. **Применяется к новым** загрузкам. Для старых — пересобери (удали все `.webp` → конвертируй существующие).

### WebP: зачем вообще

**Экономия трафика 30–70%** по сравнению с jpg/png. При том же визуальном качестве.

**Плюс:** быстрее загрузка → лучше SEO (Core Web Vitals).

**Минус:** нужно расширение на сервере + лишние файлы на диске.

**Для типичного сайта** — **включай**, если GD/Imagick есть. Это **бесплатный** прирост скорости.

### Lazy loading: зачем

**Откладывает загрузку** изображений, которые **вне видимой области**. Пользователь не видит — браузер не загружает.

**Экономия трафика** на первом экране. **Ускоряет** LCP.

**Безопасно:** браузер **сам** загрузит картинку, когда она войдёт в viewport. Пользователь **не заметит** разницы.

**Не применяется в hero/карусели** — там картинка **уже** видна, lazy только **вредит** (откладывает загрузку нужного).

### WebP в подпапках — работает?

**Да.** Все функции (`getWebpStats`, `deleteAllWebp`, `countImagesWithoutWebp`, `convertExistingImagesStep`) обходят `images/` **рекурсивно**.

- `images/products/photo.jpg` → `images/products/photo.webp` — ✅ создаётся.
- Учитывается в статистике, удаляется, конвертируется.
- **Корень сайта** — только **верхний уровень** (там логотипы/OG, не контент).

## 🎨 Дизайн

### Цвета не меняются

**Причина:** **кеш** **CSS** **в** **браузере**.

**Решение:**
- **Ctrl+F5** (**жёсткое** **обновление**).
- **Очисти** **кеш** **в** **админке**.
- **Проверь** **в** `index.php` — **цвета** **в** `<style>` **обновлены**?

### Логотип не отображается

**Причины:**
- **Неверный** **путь**.
- **Файл** **не** **загружен**.
- **Формат** **не** **поддерживается**.

**Решение:**
- **Проверь** **путь** **в** **настройках**.
- **Загрузи** **через** **медиа-менеджер**.
- **Используй** PNG/SVG.

### Шрифт иконок не работает

**Причины:**
- **Отсутствует** `fonts/lucide.css` **или** `fonts/brands.svg`.
- **Кеш** **браузера**.

**Решение:**
- **Проверь** **наличие** **файлов**.
- **Ctrl+F5**.
- **Открой** **DevTools** → **Network** → **проверь** **404**.

## 🔐 Безопасность

### Меня заблокировало (мой IP в бане)

**Решение:**
1. **Зайди** **с** **другого** **IP** (**мобильный** **интернет**).
2. **Безопасность** → **Журнал** **блокировок** → **найди** **свой** **IP**.
3. **Нажми** **«Разблокировать»**.

**Или** — **через** `config/data/login_attempts.json`:
- **Удали** **свой** **IP** **из** `attempts`.
- **Сохрани** **файл**.

### CSRF-ошибка при сохранении

**Причины:**
- **Сессия** **истекла**.
- **Cookie** **заблокированы**.
- **Открыл** **сайт** **в** **нескольких** **вкладках**.

**Решение:**
- **Обнови** **страницу** (**Ctrl+F5**).
- **Залогинься** **снова**.
- **Используй** **одну** **вкладку** **для** **админки**.

### Warning: preg_match / Undefined variable

**Причина:** `DEBUG_SITE`/`DEBUG_ADMIN = true`.

**Решение:**
- **На** **проде** — `DEBUG_* = false`.
- **На** **локалке** — **проверь** **лог** `data/logs/php_errors.log`.

## 📦 Бэкапы

### Бэкап не создаётся

**Причины:**
- **Мало** **места** **на** **диске**.
- **Неверный** `storage_path`.
- **Нет** **прав** **на** **запись**.

**Решение:**
- **Проверь** **свободное** **место** (**Резервное** **копирование** → **статистика**).
- **Проверь** **путь**.
- **Проверь** **права** **CHMOD** (`755`).

### Восстановление «зависло»

**Причина:** **большой** **сайт** (**> 10 000** **файлов**), **PHP** **timeout**.

**Решение:**
- **Увеличь** `max_execution_time` **до** 600.
- **Увеличь** `memory_limit` **до** 512M.
- **Используй** **системный** **крон** **для** **бэкапов**.

### Не могу расшифровать бэкап

**Причина:** **неверный** **пароль** **или** **повреждён** **архив**.

**Решение:**
- **Проверь** **пароль** (**тот** **же**, **что** **при** **создании**).
- **Попробуй** **открыть** **в** **7-Zip**/**WinRAR**.
- **Если** **архив** **повреждён** — **восстанови** **из** **другого** **бэкапа**.

## ⚡ Производительность

### Сайт работает медленно

**Причины:**
- **Кеш** **выключен**.
- **Много** **модулей** **на** **странице**.
- **Не** **включена** **минификация**.
- **Хостинг** **слабый**.

**Решение:**
- **Включи** **кеширование** (**Настройки** → **Кеширование**).
- **Включи** **минификацию** (**Настройки** → **Минификация**).
- **Убери** **лишние** **модули**.
- **Включи** **объединение** **ассетов**.

### Админка тормозит

**Причина:** **много** **страниц** **в** **списке**.

**Решение:**
- **Установи** `per_page = 25` (**по** **умолчанию**).
- **Используй** **поиск**/**фильтры**.

### Конструктор «зависает» при 20+ модулях

**Причина:** **большой** **JSON** **в** `constructor-data`.

**Решение:**
- **Разбей** **страницу** **на** **несколько**.
- **Сохрани** **промежуточно**.
