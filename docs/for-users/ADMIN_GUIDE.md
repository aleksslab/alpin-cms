# Обзор админки AlPin CMS

## 🔐 Вход

**URL админки:** `https://твой-сайт/config/index.php`

**Форма логина:**
- **Логин** — задан в `config/data/credentials.json`.
- **Пароль** — задан при генерации хеша.

**Сессия** автоматически продлевается при активности.  
**Таймаут** (по умолчанию 20 минут бездействия) — настраивается в **Безопасность**.

**Выход** — кнопка **«Выйти»** в правом верхнем углу.

---

## 🎨 Интерфейс

### Верхняя панель

- **Логотип CMS** — кликабельный (ведёт на главную админки).
- **Режим CMS** — индикатор.
- **Переключатель темы** 🌙/☀️ — светлая/тёмная, сохраняется в `localStorage`.
- **Выйти** — завершение сессии.

### Левое меню (сайдбар)

**Две группы:**

**1. Модули сайта:**
- **Настройки сайта** — глобальные параметры (контакты, цвета, SEO, соцсети).
- **Страницы** — список страниц, конструктор.
- **Управление модулями** — установка/удаление модулей.
- **Меню сайта** — управление навигацией.

**2. Система:**
- **Проводник (Файлы)** — файловый менеджер с редактором кода.
- **Безопасность** — учётка админа, anti-brute-force, IP-бан.
- **Резервное копирование** — бэкапы, восстановление, расписание.
- **Логи системы** — журнал действий.

**Сворачивание** — клик по заголовку группы («Модули сайта» / «Система»).

**На мобильных** — сайдбар сворачивается в бургер (☰).

### Рабочая область

- **Активная вкладка** — содержимое.
- **Flash-сообщения** — всплывающие тосты (успех/ошибка).
- **Аккордеон** — секции внутри вкладок (клик по заголовку).

## 📋 Вкладки

### 1. Настройки сайта (`config_vars`)

**Секции (аккордеон):**

| Секция | Что настраивается |
|--------|-------------------|
| **Контактная информация** | Название, слоган, телефон, email, адрес |
| **Визуальные элементы** | Логотип, favicon |
| **Цветовая схема** | 8 цветов (основной, hover, фоны, текст, границы) |
| **Настройки хедера** | Вариант, фиксация, бургер |
| **Настройки футера** | Вариант, копирайт |
| **SEO настройки** | Meta Title/Description/Keywords |
| **Open Graph & Twitter** | OG и Twitter Card |
| **Социальные сети** | До 13 сетей |
| **Минификация** | CSS/JS + исключения по модулям |
| **Кеширование страниц** | Включение, TTL, статистика, очистка |
| **Интеграция с планировщиком** | Токен крона, URL для бэкапов и публикации, перегенерация |
| **Произвольный код** | Custom CSS/JS |

**Сохранение** — кнопка внизу. **Сброс** — обновление страницы без сохранения.

**Поля с HTML** — название, слоган, копирайт (с санитайзером).  
**HTML запрещён** — телефон, email, адрес (валидация).

### 2. Страницы (`pages`)

**Список страниц:**
- Таблица (desktop) / карточки (mobile).
- **ID**, **Title**, **Slug**, **Template**, **Status**.
- **Действия:** Редактировать, Клонировать, Удалить, Сделать главной (★).
- **Пагинация** — 10/25/50/100/200 на страницу.

**Создание/Редактирование:**
- **Основные настройки:** Title, Slug, Status, Meta.
- **Конструктор:** ряды, колонки, модули (см. [CONSTRUCTOR_GUIDE.md](CONSTRUCTOR_GUIDE.md)).

**Статусы страницы:**

В форме редактирования (секция «Основные настройки») — **4 статуса публикации** (radio-кнопки):

| Статус | Что значит | Видна на сайте |
|--------|------------|----------------|
| **Черновик** | Страница в работе, не опубликована | Нет |
| **По расписанию** | Опубликуется автоматически в указанное время | Нет (до `publish_at`) |
| **Опубликована** | Видна всем посетителям | Да |
| **Снята с публикации** | Была опубликована, но снята (архив) | Нет |

**Как задать дату публикации:**

1. Выбери статус **«По расписанию»**.
2. Появится поле **«Опубликовать»** (`datetime-local`) — обязательно.
3. Опционально — **«Снять с публикации»** (`datetime-local`).
4. Сохрани страницу.

**Что происходит дальше:**
- В момент `publish_at` страница автоматически станет **«Опубликована»**.
- Если задан `unpublish_at` — в этот момент страница перейдёт в **«Снята с публикации»**.
- Автопубликация работает через крон (см. «Автоматизация» ниже).

**Ограничения:**
- `publish_at` в прошлом → ошибка сохранения.
- `unpublish_at` в прошлом → ошибка.
- `unpublish_at` ≤ `publish_at` → ошибка.

**Статус «Опубликована» + «Снять с публикации»:**

Если страница **уже опубликована**, но нужно **автоматически снять** её в будущем — поставь статус «Опубликована» и заполни поле «Снять с публикации». Дата `publish_at` при этом не нужна (она обнулится автоматически).

**Бейджи в списке страниц:**

| Бейдж | Когда |
|-------|-------|
| **Опубликована** | `status = published`, снятие не запланировано |
| **Снятие запланировано** | `status = published` + `unpublish_at` в будущем |
| **Запланирована** | `status = scheduled` |
| **Черновик** | `status = draft` |
| **Снята с публикации** | `status = archived` |

**Особенности:**
- **Главная страница** — `slug` пустой, кнопка ★ переносит статус.
- **Клон** — создаёт `{id}-copy` со статусом «Черновик».
- **Удаление** — нельзя удалить главную.

**Удаление страницы — в корзину:**

При нажатии **«Удалить»** страница **не удаляется физически**, а **перемещается в корзину**. Восстановить можно в любой момент.

**Что видно в списке:**
- Кнопка **«Корзина»** в шапке вкладки.
- **Бейдж** с числом удалённых страниц (если больше нуля).

**Что внутри корзины:**
- Список удалённых страниц: **название**, **ID**, **дата удаления**, **кто удалил**.
- Чекбоксы для выбора.
- Кнопки: **«Восстановить»**, **«Удалить выбранные»**, **«Очистить корзину»**.

**Восстановление:**
- Выбери страницы → **«Восстановить»** → подтверждение.
- Если оригинальный ID занят (например, создал заново `about`) → восстановится как **`about-restored`**, **`about-restored-2`** и так далее. Всплывёт уведомление.
- Slug пересчитывается **автоматически** — чтобы URL не конфликтовал.

**Окончательное удаление:**
- **«Удалить выбранные»** — удаляет только отмеченные.
- **«Очистить корзину»** — удаляет всё.
- ⚠️ **Это необратимо.** Подтверждение перед выполнением.

**Автоочистки нет** — корзина хранится до ручной очистки.

**Что нельзя удалить:**
- **Главную страницу** — кнопка удаления заблокирована.
- **Главное меню** — см. раздел «Меню сайта».

### Автоматизация публикации

**Два способа запустить автопубликацию и автоснятие:**

**1. Виртуальный крон (рекомендуется для небольших сайтов):**

Работает **автоматически** при входе в админку. Проверяет страницы с истёкшими датами и публикует/снимает их. Не чаще 1 раза в 5 минут.

**Настройка не требуется** — работает всегда.

**2. Системный крон (рекомендуется для прода):**

Настрой планировщик на хостинге (crontab) на URL:

```
https://твой-сайт/config/cron/publish.php?token=<твой_токен>
```

**Где взять URL:**
**Настройки сайта** → **Интеграция с планировщиком** → блок **«Автопубликация страниц»**.

**Рекомендуемая частота:** каждые 5–15 минут.

**Плюсы системного крона:** работает, даже когда админ не заходит в админку. 

**Плюсы виртуального:** не требует настройки.

**Оба работают одновременно** — не мешают друг другу.

**Токен и перегенерация:**

Оба крона (и бэкап, и публикация) используют **один общий токен**. Если понадобится его сменить (например, утёк):

1. **Настройки сайта** → **Интеграция с планировщиком**.
2. Клик **«Перегенерировать»** → подтверждение.
3. **«Сохранить настройки»** — токен вступит в силу **только после сохранения**.
4. Обнови URL в планировщике хостинга (иначе крон перестанет работать).

⚠️ **Перегенерация сломает обе крон-задачи** — резервное копирование и автопубликацию. Предупреждение показывается в UI.

### 3. Управление модулями (`modules`)

**Список установленных модулей:**
- **Иконка/превью**, **название**, **ID**, **описание**.
- **Статус:** распакован / в архиве / авто.
- **Использование:** «используется на N стр.» / «не используется».
- **Действия:**
  - **Распаковать** — если модуль в архиве, но не распакован.
  - **Пересобрать .min** — пересобрать `.min.css`/`.min.js` (если включена минификация).
  - **Удалить** — только если модуль не используется.

**Установка модуля:**
- Кнопка **«Установить модуль»** сверху.
- Модалка с **drag-n-drop** ZIP-архива (до 10 МБ).
- Проверка `manifest.json`, `preview.png`.
- Прогресс-бар загрузки.

**Обновление модуля:** загрузка того же `manifest.id` → замена.

### 4. Меню сайта (`menu`)

**Список меню:**
- **ID**, **Название**, **★** (сделать главным).
- **Действия:** Редактировать, Удалить (главное — нельзя).

**Создание/Редактирование:**
- **Название**, **ID** (латиница).
- **Пункты меню:**
  - **Тип:** Страница, Раздел (якорь), Ссылка, Выпадающее, Разделитель.
  - **Порядок** (вверх/вниз).
  - **Dropdown** — вложенные пункты.
  - **Сворачивание** dropdown в списке (chevron).

**Главное меню** — используется в хедере (сворачивается в бургер).

**Удаление меню — в корзину:**

Работает так же, как со страницами: кнопка **«Корзина»** в шапке вкладки, бейдж со счётчиком, модалка со списком.

**Главное меню** удалить **нельзя** — кнопка удаления заблокирована. В корзину главное меню не попадает.

### 5. Проводник (`filemanager`)

**Возможности:**
- **Список файлов** — плитки с иконками, превью картинок.
- **Хлебные крошки** — навигация.
- **Контекстное меню** (правый клик):
  - Открыть (просмотр/редактирование).
  - Переименовать.
  - Копировать путь.
  - Свойства (размер, дата, права).
  - Изменить атрибуты (CHMOD).
  - Удалить.
- **Создать** — папку/файл.
- **Загрузить** — drag-n-drop или выбор.
- **Редактор Ace** — подсветка PHP/CSS/JS/JSON/HTML.
- **Undo/Redo**, **Ctrl+S** (сохранить), **Ctrl+Z**/**Ctrl+Y**.

**Ограничения:**
- **Whitelist** расширений: `php, css, js, json, html, txt, htaccess, jpg, jpeg, png, webp, gif, svg`.
- **Blacklist** путей: `config/data`, `config/core`, `config/backups`, `data/logs`.
- **Чувствительные файлы** (`.pepper`, `credentials.json`, `login_attempts.json`, `backup_config.json`) — только чтение.

**Осторожно:** редактирование `config/core/*` может сломать CMS.

### 6. Безопасность (`security`)

**Учётная запись:**
- **Логин** — сменить (потребуется новый пароль).
- **Новый пароль** — оставить пустым, если не меняешь.
- **Таймаут сессии** (минуты).

**Anti-Brute Force:**
- **Порог временного бана** (попыток).
- **Длительность таймера** (минут).
- **Порог вечной блокировки** (банов).
- **Окно отслеживания** (часов).

**Журнал блокировок:**
- **IP-адрес**, **статус** (временный/постоянный), **счётчик**, **осталось времени**.
- **Разблокировать** — вручную снять бан.
- **Заблокировать** — вручную добавить IP в чёрный список.

**Уведомления** о смене учётки приходят на `email` из настроек.

### 7. Резервное копирование (`backups`)

**Настройка:**
- **Режим:** Полный / Выборочно (папки).
- **Путь** к папке бэкапов (по умолчанию `config/backups/`).
- **Шифрование** AES-256 (пароль).
- **Виртуальный крон** — авто-бэкап при входе админа.
- **Системный крон** — URL для планировщика хостинга.

**Мгновенный бэкап:**
- Кнопка **«Запустить резервное копирование»**.
- Прогресс-бар с шагами.

**Список архивов:**
- **Дата**, **имя**, **размер**, **защита** (🔒/🔓).
- **Действия:** Скачать, Восстановить, Удалить.

**Восстановление:**
- ⚠️ **Полная перезапись** файлов сайта.
- Для зашифрованного архива — ввод пароля.
- **НЕ отменяется** — делай бэкап перед восстановлением.

### 8. Логи системы (`logs`)

**Настройка логирования:**
- **Включить** логирование.
- **Путь** к папке логов.
- **Максимальный размер** файла (МБ).
- **Количество архивов** (ротация).
- **Какие действия** логировать (чекбоксы по категориям).

**Журнал событий:**
- **Фильтры:** уровень (INFO/WARNING/ERROR/CRITICAL), действие, поиск.
- **Пагинация:** 10/25/50/100 записей.
- **Колонки:** время, уровень, пользователь, IP, действие, сообщение.

**Уровни:**
- **INFO** — обычные действия.
- **WARNING** — предупреждения.
- **ERROR** — ошибки.
- **CRITICAL** — критические.

## 🎯 Типичные задачи

### Создать новую страницу

1. **Страницы** → **Создать страницу**.
2. Заполни **Title** (обязательно).
3. **Slug** — сгенерируется автоматически (можно изменить вручную).
4. **Status** — «Опубликована» (или «Черновик»).
5. Добавь модули через **конструктор**.
6. **Сохранить**.

### Назначить главную

**Страницы** → ★ (звёздочка) рядом с нужной страницей.

**Главная** — страница с пустым `slug` (открывается по `/`).

### Изменить цвета

**Настройки сайта** → **Цветовая схема** → выбери цвета через color-picker или введи HEX → **Сохранить**.

### Установить модуль

1. **Управление модулями** → **Установить модуль**.
2. **Перетащи** ZIP-архив в модалку.
3. Дождись распаковки.
4. Модуль появится в списке — **добавь** его на страницу через конструктор.

### Сделать бэкап

1. **Резервное копирование** → **Запустить резервное копирование**.
2. Дождись завершения.
3. **Скачай** архив на компьютер (**Резервное копирование** → иконка загрузки).

### Настроить авто-бэкап

**Резервное копирование**:
- **Виртуальный крон** — вкл, периодичность 24ч/168ч.
- **Системный крон** — вкл, скопируй URL в планировщик хостинга.

## ⚠️ Безопасность

**Регулярно:**
- Меняй пароль (раз в 3-6 месяцев).
- Проверяй логи на подозрительные действия.
- Делай бэкапы перед крупными изменениями.
- Обновляй модули и CMS.

**Никогда:**
- Не делись логином/паролем.
- Не отключай HTTPS на проде.
- Не оставляй `DEBUG_SITE = true` на проде.
