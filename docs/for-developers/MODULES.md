# Разработка модулей

Модуль в AlPin CMS — это **ZIP-архив** с **manifest.json** в корне и набором
файлов для **админки** (`admin/`) и **сайта** (`site/`). После установки
файлы распаковываются в общие папки CMS.

## 📦 Структура ZIP

```
my-module.zip
├── manifest.json           # Метаданные (обязательно)
├── preview.png             # Превью 200×200 (опционально)
│
├── admin/                  # Форма настроек в админке
│   ├── module.php          # Форма (обязательно, если has_settings=true)
│   ├── style.css           # Стили формы (опционально)
│   └── script.js           # JS формы (опционально)
│
└── site/                   # Рендеринг на фронте
    ├── module.php          # Рендер (обязательно)
    ├── style.css           # Стили (опционально)
    └── script.js           # JS (опционально)
```

### Куда что распаковывается

| Из ZIP | Куда попадает | Как используется |
|--------|---------------|------------------|
| `admin/module.php` | `config/modules/{id}/module.php` | Форма в модалке настроек |
| `admin/style.css` | `config/modules/{id}/style.css` | Стили формы (только в админке) |
| `admin/script.js` | `config/modules/{id}/script.js` | JS формы (только в админке) |
| `site/module.php` | `modules/{id}.php` | Рендер на фронте |
| `site/style.css` | `css/{id}.css` | Стили на фронте |
| `site/script.js` | `js/{id}.js` | JS на фронте |

**Ключевое:**
- Файлы `admin/*` живут **в папке модуля в админке**, имя сохраняется.
- Файлы `site/*` **переименовываются в `{id}.{ext}`** и кладутся в **общие** `css/`, `js/`, `modules/`.
  - `my-module` → `css/my-module.css`, `js/my-module.js`, `modules/my-module.php`.
- **Не давай** `site/module.php` имя, отличающееся от `id`. Иначе **файлы не найдутся**.
- **Дубликаты `style.css`** между модулями **исключены**, потому что имя = id.

## 📄 `manifest.json`

**Обязательные** поля:

```json
{
    "id": "my-module",
    "name": "Мой модуль",
    "icon": "icon-box",
    "description": "Краткое описание модуля",
    "version": "1.0.0",
    "author": "Ваше имя",
    "has_settings": true,
    "auto_unpack": false
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | **Уникальный ID** (`a-z`, `0-9`, `-`, `_`). Используется в именах файлов. |
| `name` | string | Название в админке. |
| `icon` | string | Lucide-класс (`icon-box`, `icon-star`, ...). |
| `description` | string | Короткое описание. |
| `version` | string | Semver-версия. |
| `author` | string | Автор. |
| `has_settings` | bool | Есть ли форма настроек. Если `false` — модуль без настроек, `admin/module.php` не нужен. |
| `auto_unpack` | bool | **См. «Распаковка модуля» ниже.** |

### Валидация при загрузке

- `id` — только `[a-z0-9\-_]+`, регистр **важен** (нижний).
- Размер ZIP — не более **10 МБ**.
- `manifest.json` — **в корне** ZIP.
- `site/module.php` — **обязателен**.
- `plugin.json` **в** **архиве** **модуля** — **отказ** (**это** **плагин**, **не**
  **модуль**).
- `manifest.id` **должен** **совпадать** **с** **ID** **установки**.
- **Версия** **не** **ниже** **установленной** — **даунгрейд** **запрещён**.
- Защита от **ZIP Slip** — пути с `..`, `/`, `C:\`, NUL-байты **блокируются**.

## 🚀 Установка модуля

### Через админку

1. **Управление модулями** → **Установить модуль**.
2. Перетащи ZIP.
3. Дождись распаковки.
4. Модуль появится в списке.
5. **Добавь на страницу** через конструктор.

### Распаковка модуля — когда код попадает в папки

Архив — источник истины. Код в `config/modules/{id}/`, `modules/{id}.php`,
`css/{id}.css`, `js/{id}.js` появляется при распаковке.

| Сценарий | Поведение |
|----------|-----------|
| Установка из каталога (модуля нет) | Только архив и запись в `modules.json`. Код распакуется при первом добавлении на страницу. |
| Обновление из каталога, модуль используется | Распаковка сразу, старый код уходит в резервную копию. |
| Обновление из каталога, модуль не используется | Обновляется только архив, старый код удаляется. Новый распакуется при добавлении на страницу. |
| Загрузка ZIP вручную | `auto_unpack: true` — сразу; иначе если модуль уже используется — сразу; иначе только архив. |
| Кнопка **Распаковать** | Распаковывает архив вручную. |

`auto_unpack` поэтому влияет только на ручную загрузку ZIP. Каталог всегда
исходит из того, используется модуль на страницах или нет.

При распаковке старый код не удаляется заранее: он переносится в
`config/modules/_backup/`, и если копирование сорвалось, возвращается на место
(`_moduleStashCode()`, `_moduleRestoreCode()`). После успешной распаковки
резервная копия удаляется. Остатки прерванных установок в `_backup/` и `_temp/`
старше часа подчищаются автоматически.

### Вручную (для разработки)

**Не рекомендуется для прода** — при обновлении версии вручную надо чистить каждый файл. Для разработки:

1. Создай структуру:
   ```
   config/modules/my-module/
   ├── module.php          # форма настроек
   ├── style.css           # стили формы
   └── script.js           # JS формы

   modules/my-module.php   # рендер на фронте
   css/my-module.css       # стили фронта (опционально)
   js/my-module.js         # JS фронта (опционально)
   ```

2. Добавь запись в `config/data/modules.json`:
   ```json
   {
       "my-module": {
           "name": "Мой модуль",
           "icon": "icon-box",
           "description": "Описание",
           "has_settings": true,
           "auto_unpack": true,
           "version": "1.0.0",
           "author": "Вы"
       }
   }
   ```

3. Очисти кеш в админке (Настройки → Кеширование страниц → Очистить весь кеш).

**Важно:** вручную — только для **быстрой итерации**. Регулярно пересобирай ZIP, чтобы не забыть зависимость.

## 🗂 Каталог модулей

Модули, как и плагины, распространяются через каталог обновлений.

### Как это устроено

| Что | Где |
|-----|-----|
| Реестр установленных | `config/data/modules.json` |
| Локальная библиотека ZIP | `config/modules/archives/{id}.zip` |
| Превью | `config/modules/previews/{id}.png` |
| Публичный каталог | `catalog/mod_{id}.zip` + `catalog.json` |
| Кеш каталога | `config/data/updates_cache.json` |

**Префикс `mod_`** отделяет модули от плагинов (`plg_`) в одной папке
`catalog/`. Внутри ZIP префикса нет: архив называется `mod_hero.zip`, а
`manifest.id` — `hero`.

### Установка и обновление из каталога

1. Вкладка **Модули** → **Обновить каталог**.
2. Список **«Доступные для установки»** — модули, которых нет ни в коде, ни в
   архиве.
3. **Установить** — скачивает ZIP (`downloadModuleZip()`), проверяет
   (`validateModuleArchive()`) и кладёт архив в библиотеку
   (`installModuleFromZip(..., false)`). Код распакуется при добавлении модуля
   на страницу или по кнопке **Распаковать**.
4. Если модуль уже установлен и в каталоге версия выше — у него появляется
   бейдж `v1.0.0 → v1.1.0` и кнопка **Обновить**.

Установленный модуль считается установленным, если есть **код** или **архив**.
«Новый» — только если нет ни того, ни другого (см. `refresh_updates_cache()`).

Обновление зависит от использования:

- модуль есть на страницах (`findModuleUsage()`) — код заменяется сразу,
  старый уходит в `config/modules/_backup/` и удаляется только после успешной
  распаковки;
- модуль не используется — перезаписывается только архив, старый код
  удаляется, новый распакуется при добавлении на страницу.

Плагин `updates` использует ту же логику.

### Удаление

Две кнопки:

| Кнопка | Что удаляет | Что остаётся |
|--------|-------------|--------------|
| **Удалить код** | `config/modules/{id}/`, `modules/{id}.php`, `css/{id}.css`, `js/{id}.js` и их `.min` | архив, превью, запись в `modules.json` |
| **Удалить полностью** | всё выше + архив + превью + запись | ничего |

**Правило:** если модуль используется на страницах (`findModuleUsage()`),
обе кнопки заблокированы — сначала убери модуль со страниц.

### Публикация в каталоге

1. Собери ZIP: `manifest.json` в корне, `admin/`, `site/`, `preview.png`.
2. Положи архив в `catalog/` с именем `mod_{id}.zip`.
3. Пересобери `catalog.json` (`catalog-builder.php`, локальный скрипт, в
   репозиторий не входит).
4. Проверь запись: `type: "module"`, `download_url` заканчивается на
   `mod_{id}.zip`.

Поля записи `catalog.json`:

```json
"hero": {
    "type": "module",
    "name": "Герой (Hero)",
    "description": "Полноэкранный блок с заголовком",
    "version": "1.0.0",
    "download_url": "https://raw.githubusercontent.com/AlekSSLab/alpin-cms/.../catalog/mod_hero.zip",
    "icon": "icon-layout-dashboard"
}
```

**Требования:**

- `manifest.id` **уникален** среди модулей **и** плагинов — `catalog-builder.php`
  пропускает дубликаты;
- версия в `manifest.json` поднимается при каждом исправлении, иначе
  обновление не придёт (`validateModuleArchive()` сравнит версии);
- имя файла — ровно `mod_{id}.zip`;
- ZIP не содержит `plugin.json`.
